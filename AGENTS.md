# IRLid — read before any job

1. Read `docs/rules.md` (the IRLid rules) and `docs/requirements/offline-first.md` first.
2. If a task would break a rule, stop and ask Spencer. Don't work around it.
3. New branch and PR every time. Never commit to main. Never merge; Spencer merges each PR by name (rule W2).
4. Keep to the task's scope. Don't touch other branches.
5. Run the tests (`npm test`, `npm run test:org-worker`, `npm run test:api`) before opening a PR (rule W3).
